**Підсумок: 8/8, помилок маршрутизації немає.** Правила з `SYSTEM_AGENT` і доповнені описи
інструментів (rag_search → sql_query для підрахунків/переліків; sql_query → rag_search для змісту)
відпрацювали коректно, включно з послідовним викликом у складених питаннях.

## Примітки

1. Конфігурація: у `app/core/config.py` поле `checkpoint_database_url` було без типу анотації,
   pydantic падав при імпорті (`PydanticUserError`); додано `: str`. Потрібно для запуску CLI.
2. У момент перевірки `scripts/cli_agent.py` був переwrites на langgraph-runtime
   (`app/agent/runtime.py` → `app/agent/graph.py`, якого ще немає) — CLI не запускався.
   Питання 5–8 проганялись тим самим `run_agent` (manual_react) з ідентичною конфігурацією
   SYSTEM_AGENT + TOOLS. Після завершення рефакторингу варто повторити прогін через CLI.
3. Середовище: docker-compose (postgres:17 + qdrant), у каталозі 11 документів, Qdrant-колекція
   `knowledge_base` на місці; запуск ішов проти readonly-користувача `assistant_ro`.
4. Q4: sql_query повернув обидві постанови від 30.09 (FETCH FIRST 1 ROW WITH TIES), і агент сам
   помітив дві найновіші та окремо опитав кожну через rag_search — обидві відповіді в фінальній
   відповіді. Помилки «взяв лише одну» не сталося.
